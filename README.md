# Flick & Fly — LPC1768 space shooter

Flick & Fly is an Embedded Systems Lab game demonstration using an LPC1768, MPU6050, and TFT. The current isolated [M5 firmware](firmware/tests/restart_highscore_m5/README.md) has calibrated tilt steering, automatic firing, enemies and collisions, score and lives, `GAME_OVER`, SW2 restart, and a persistent best score. The owner reports that M5 was flashed, that restart and gameplay worked on the board, and that a high score survived switching board power off and on. The exact M5 HEX used for that physical test is **unidentified**. See the [dated current-state and evidence index](docs/CURRENT_STATE_AND_EVIDENCE_2026-10-29.md) and [M5 physical verification record](firmware/tests/restart_highscore_m5/PHYSICAL_VERIFICATION.md) for the evidence limits.

The [M6 offline proof of concept](ml/README.md) provides a one-command generated dataset, shallow decision-tree training, threshold-baseline evaluation, C export, host tests, and refreshed guide results (`python ml/run_all.py`). On 175 held-out **generated** examples, the tree and baseline made identical predictions; this is expected because the labels were generated from the baseline rule. It is not deployed in M5 and provides no real-sensor accuracy result. The proposed four-command threshold-versus-tree study in the [synopsis](docs/Updated_ESDL_Synopsis_ML_IMU_Gesture_Recognition.docx) and [research plan](docs/RESEARCH_PLAN.md) remains future work. The current game fires automatically; flick-to-fire and adaptive difficulty are not implemented.

## Player guide

Open [index.html](index.html) in a browser for an illustrated guide to the current controls. It is an instructional website, not a live sensor connection or browser game; its motion illustrations do not show measured sensor readings. [app.js](app.js) drives the selectable illustrations and checklist, and [styles.css](styles.css) supplies the layout. No build step is required for the guide.

For the project's status and historical records, start with [PROJECT_CONTEXT.md](PROJECT_CONTEXT.md), the [firmware overview](firmware/README.md), and the [evidence index](docs/CURRENT_STATE_AND_EVIDENCE_2026-10-29.md). The [M5 hardware signal map](manual/hardware-connections.md#current-m5-signal-map-for-the-ieee-report) lists the documented MPU6050, TFT, and SW2 routes and their physical verification limits. Score retention through firmware reprogramming and the fitted modules' electrical compatibility remain unverified.
